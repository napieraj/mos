removal list required by CLAUDE.md rule 7 ("load-bearing comments →
propose removals as a list, don't act"). No source changes accompany
it; execution is per-phase, on sign-off.

## 2. Diagnosis: four bloat sources, one protected category

The framing "comments are prose describing the code" is partially
right — narration exists — but it is not the dominant mass. Ranked by
recoverable lines:

### B. Header↔.c duplication (largest win, lowest risk)

The same contract is written out in full in both the header docstring
and the implementation. Verified instances:

- `mos_cli_stdout_finalize`: the ferror/errno classification rationale
  appears at `cli/io.h:41-59` AND `cli/io.c:67-84` (~20 lines × 2; the
  .c copy even ends "This matches the contract documented in
  mos_cli_io.h").
- `mos_internal_config_current_profile`: full contract at
  `src/mos_pure.h:222-228` AND `src/mos_config.c:98-112`.
- The GET CONFIGURATION walker: contract at `src/mos_pure.h:149-156`
  AND the layout + safety contract in `src/mos_config.c:1-43` overlap
  substantially.
- `mos_internal_state_from_sense_closed`: `src/mos_pure.h:97-102` AND
  `src/mos_sense.c:48-68`.

The pattern repeats across most `mos_pure.h` prototypes. Estimated
recoverable: 250–350 lines.

### D. History/changelog embedded in code

Dated decisions, session references, and old-bug narratives that mean
nothing to a reader without the transcript:

- "CLI-design decision 2026-06-10" (`cli/io.c:50`)
- "(Commit D)" (`cli/io.h:33`)
- "Appended in v0.3.1-dev …" (`include/mos.h:54-58`)
- "seam audit, Item 2: the old gate diverged on exactly 11 inputs"
  (`src/mos_state_core.c:103-105` — the *result* is load-bearing, the
  audit provenance is history)
- "The old fixed 4096 buffer silently truncated" (`cli/io.c:20-24`)
- "has bitten us before" (`src/mos_internal.h:165`)

The durable content moves to ARCHITECTURE.md / CHANGELOG /
doc/research (most destinations already exist); code keeps a one-line
why plus a `§` pointer. Side benefit: text relocated into live docs
falls under the `scripts/doc-staleness.sh` gate, which does not scan
code. Estimated recoverable from code: 100–150 lines.

### E. Repeated boilerplate

The int32 ABI width-pin block (rationale + `#if __cplusplus`
static_assert / `#else` `_Static_assert` pair) appears four times in
`include/mos.h` (`mos_error`, `mos_state_enum`, `mos_xfer_dir`,
`mos_event_kind`), ~12 lines each plus inter-references ("see the pin
above"). One `MOS_ABI_PIN_I32(type)` macro plus a single rationale
comment collapses ~55 lines to ~15. This is the only phase that
touches non-comment tokens; it is isolated in its own commit.

### C. Narration (smallest category)

Comments restating what the adjacent code does: file headers like
`cli/io.c:1-8` ("Delegates the actual escaping to the library's
single canonical implementations…" — the `#include` and call say so),
step-by-step "Size first, then escape" framing where the why is
already captured. Delete. Estimated: 50–100 lines.

Also fix while passing: stale file headers (`cli/io.c` opens with
"mos_cli_io.c"; `cli/io.h:59` references "mos_cli_io.h" — neither
file exists under that name).

### A. PROTECTED — load-bearing, not bloat

Explicitly out of scope for deletion. This codebase's heavy "why"
commentary is doctrine (AGENTS.md, eight external review passes
leaned on it), and these blocks state constraints the code cannot:

- Kernel-behavior citations with file:line into Apple OSS — the nub
  gate (`src/mos_state_core.c:102-125`), the exclusivity-refusal note
  (`mos_state_core.c:74-81`).
- Adversarial-input safety contracts — the GET CONFIGURATION
  walker's hostile-length rules (`mos_config.c`), the dual-length
  rule (`mos_pure.h:197-215`), GESN validity gates.
- ABI/FFI rationale (kept once, post-dedup).
- Ownership/lifetime contracts on internal prototypes
  (`mos_internal.h:149-157`, the MOS_*_AUTO transfer pattern).
- Spec byte-layout tables — kept in exactly one home: the `.c` that
  does the parsing (`mos_sense.c`, `mos_config.c`); trimmed from
  headers where duplicated.

If execution finds a block that reads as history but anchors a test
or an ADR, it stays and gets a pointer instead.

## 3. Doctrine to prevent regrowth: tiers + single home

### 3.1 Commentary tiers (budget scales with audience)

The public/internal split is itself a comment-budget rule. The repo
currently documents internal seams at public-API depth; that is where
most of the recoverable mass sits.

- **Tier 1 — `include/mos.h` (public ABI).** The documentation of
  record for external consumers, who see opaque types and accessors
  and cannot read the structs. Full caller contracts, ownership and
  lifetime rules, threading, ABI/FFI rationale stay — density here is
  a feature. Cuts in mos.h come only from categories D (history) and
  E (boilerplate), not from thinning contracts.
- **Tier 2 — internal seam headers (`mos_pure.h`, `mos_internal.h`,
  `cli/*.h`).** Audience is a contributor who can open the `.c`.
  Prototypes get one-to-three-line contracts (args, return domain,
  ownership if non-obvious); the full reasoning lives in the `.c` or
  ARCHITECTURE.md. Exception: cross-cutting safety contracts that
  govern multiple implementations (the dual-length rule,
  `mos_pure.h:197-215`) keep their one full statement in the header
  because no single `.c` owns them.
- **Tier 3 — `.c` internals.** Why-only comments at the code; no
  restated contracts, no API-style docstrings on static functions.

### 3.2 The single-home rule

Each fact gets exactly one home:

| Content                                  | Home                                  |
|------------------------------------------|---------------------------------------|
| Caller contract (args, returns, ownership)| header docstring, once                |
| Implementation why (shape of the code)   | `.c`, at the relevant lines, once     |
| Decisions, dates, review/audit provenance | ARCHITECTURE.md / CHANGELOG / doc/research; code carries a `§` pointer |
| Spec byte layouts                        | the parsing `.c`                       |
| File header                              | ≤ 3 lines: what + the one constraint  |

Cross-references replace restatement: "see ARCHITECTURE.md §4.2",
never a second copy of §4.2's argument.

Both rules land as ~20 lines in CONTRIBUTING.md in Phase 0.

## 4. Phases

Each phase is one commit, comment-only (Phase 3a excepted), with
`cmake --build build && ctest --test-dir build` green before and
after. Review check per commit: every hunk touches only comment
text.

- **Phase 0 — doctrine.** Add the single-home rule to
  CONTRIBUTING.md. No source changes.
- **Phase 1 — dedup + tiering (category B).** For every duplicated
  contract: in Tier 1 the contract stays in the header and the `.c`
  keeps mechanism only; in Tier 2 the header keeps a one-to-three-
  line contract and the full reasoning stays with the `.c` (or moves
  to ARCHITECTURE.md if it is architecture, not mechanism). Files:
  `mos_pure.h` ↔
  {`mos_sense.c`, `mos_config.c`, `mos_pure.c`, `mos_discinfo.c`,
  `mos_state_core.c`, `mos_watch_core.c`}; `cli/io.h` ↔ `cli/io.c`;
  `cli/human.h` ↔ `cli/human.c`; `include/mos.h` ↔ `src/mos_result.c`.
- **Phase 2 — history out of code (category D).** Move dated
  narratives to their doc homes (most already exist), leave `§`
  pointers. Where a doc home is missing, the text lands in
  ARCHITECTURE.md, not CHANGELOG (CHANGELOG is append-only and
  already has its entries).
- **Phase 3a — ABI-pin macro (category E).** `MOS_ABI_PIN_I32` in
  `include/mos.h`; the only non-comment change, isolated.
- **Phase 3b — narration + stale file headers (category C).**
- **Phase 4 — regenerate and gate.** `scripts/amalgamate.sh` to
  refresh `dist/`; `scripts/doc-staleness.sh`; full suite; verify
  every `ARCHITECTURE.md §` pointer left in code resolves. Record
  before/after line counts in the commit message (not in live docs —
  hardcoded counts are a doc-staleness deny pattern).

## 6. What this plan refuses

- No deletion of kernel citations, safety contracts, or ownership
  notes to hit a line target. If the target conflicts with category
  A, the target loses.
- No rewriting of AGENTS.md/CLAUDE.md/ARCHITECTURE.md content as part
  of this pass (Phase 2 *adds* relocated text; it does not edit
  history).
- No hand-edits to `dist/`.
